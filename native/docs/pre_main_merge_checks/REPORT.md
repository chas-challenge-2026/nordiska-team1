## Reproducible findings

### P2 — Synthetic Compose validation assumes the removed `api` service

Run from the repository root:

```sh
python3 tools/syntheticDB/tests/compose-config.py
```

Fails on the frontend-local case with:

```text
service "api" has neither an image nor a build context specified: invalid compose project
```

`tools/syntheticDB/tests/compose-config.py:20` replaces `app` with `api`, and line 42 expects build target `api`. The current frontend-local configuration defines service `app`, build target `app`, and frontend dependency `app`. The script consequently creates an incomplete extra service. The actual frontend-local Compose configuration parses successfully. Update the validation script to match the current service and target.

### P2 — Native signing tests do not build with the documented OpenSSL range

Host: OpenSSL 4.0.3, GCC, Linux x86-64.

```sh
cmake --build native/pdf_generator/build/debug -j 4
```

`native/pdf_generator/tests/pdf_signing_tests.cpp:449` fails with an invalid conversion from `const X509_name_st*` to `X509_NAME*`. The subject-name getter at line 448 now returns a const pointer; the next operation mutates it. The README states OpenSSL >= 3.0, so this host meets its stated prerequisite. Use the appropriate mutable API for supported versions, or document and enforce the actual supported range. The same suite passes with the Docker OpenSSL 3.3 toolchain.

### P3 — Signed PDFs produce PDF form warnings

The signed sample has a cryptographically valid SHA-256 signature and covers the entire document. `pdfsig` nevertheless emits `FormFieldSignature: was asked for widget and didn't had one` and `Bad bounding box for annotation`. Review compatibility with intended PDF viewers. Certificate trust fails for the local demo certificate, as expected; that is separate from signature integrity.

### Existing artifacts — old PDFs retain invalid signature placeholders

Reports generated by the initially running older worker contain an all-zero 8,192-character signature placeholder; `pdfsig` reports an invalid/missing signature and incomplete document coverage. Rebuilding does not repair stored documents, and existing tax snapshots can return the old PDF. A new statement generated after the current image was activated is a clean unsigned PDF, matching `NORDISKA_PDF_ENABLE_SIGNING=0`. Separately generated signed PDFs validate successfully. Do not attribute the old placeholder behavior to current source, or use an old cached report as proof that the rebuilt worker was tested. Decide whether retained synthetic report artifacts should be cleared before demonstration; this validation did not delete them.
